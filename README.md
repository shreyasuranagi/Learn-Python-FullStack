## 🔄 Workflow Overview

To ensure steady progress, deep understanding, and clear accountability for my trainer, my workflow is divided into four core phases:

### 1. Learning & Retention

* **Intention Setting:** Every learning session begins with a `TODO` entry in `Logs/dailylogs/` and a git commit so my trainer can track active work.
* **Active Recall:** I study using class notes and external resources, pausing every 15 minutes to make notes.
* **Documentation:** Core insights, definitions, and concepts are synchronized into my Obsidian Career Vault using the **FAIR template** (Concept Name, Summary, Real-World Analogy, Use Cases, Common Errors, Code).

### 2. Practice (`myPractice/`)

* I pull problems from my Notion Skills Database.
* I solve them in VS Code under topic-specific directories (e.g., `myPractice/js/arrays/`).
* Each problem folder includes code solutions detailing my approach and error-handling steps.

### 3. Projects (`Projects/`)

* Projects are selected from the curriculum roadmap, tracked via databases, and broken down into granular tasks inside local `todo.md` files.
* Code is developed iteratively with regular `wip` commits before finalizing features.

### 4. Review

* **1-Hour Daily Review:** Dedicated time to revisit tricky concepts, write up use cases, test debugging/output-guessing questions, and practice technical interview scenarios.
